# VOID INSPECT — 솔더 보이드 자동 분석

## 기본 개발 방식: 로컬 + Docker

이 저장소를 PC에 클론하고 그 폴더를 Codex 로컬 작업으로 여세요. Docker Desktop을 실행한 뒤 **`start_local_docker.bat`**를 더블클릭하면 백그라운드 개발 서버와 브라우저가 열립니다. 코드 수정은 자동 반영되며 작업 단위별로 GitHub에 커밋/push합니다. 자세한 규칙과 후속 작업은 [DEVELOPMENT.md](DEVELOPMENT.md)를 참조하세요.

```sh
git clone https://github.com/mauihiggins/voidareacalculate.git
```

아래 Python 직접 실행은 이전 배포본을 위한 대체 방식입니다.

기준 사진에서 제품별 패드 경계와 LED번호를 한 번 등록한 뒤, 반복 검사 사진을 정렬해 보이드를 분석하는 웹 앱입니다. 패드는 1~64개 등록할 수 있습니다. 설정이 없는 사진에는 임의의 4패드를 적용하지 않고 등록을 기다립니다. 원본 비교, 선택적인 검출 수정·재계산, 표시 사진 PNG 및 결과 CSV 저장을 지원합니다.

## Windows 실행

[Python 3.12.10 Windows installer (64-bit)](https://www.python.org/downloads/release/python-31210/)를 설치하고 `start_web_windows.bat`를 실행하세요. 처음에는 의존성 설치를 위해 인터넷이 필요합니다. 브라우저 주소는 http://127.0.0.1:8000 입니다. Python Launcher를 포함해 설치하세요. 실행 스크립트는 Python 3.12 x64를 확인하고 별도 `.venv-win312` 환경을 사용합니다. 기존 `.venv`는 건드리지 않으며, 바이너리 패키지만 설치해 NumPy 소스 빌드를 방지합니다.

서버 준비 전에 브라우저가 열리면 새로고침하세요. 종료하려면 서버 창에서 Ctrl+C를 누릅니다.

다른 환경에서는 다음과 같이 실행합니다.

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

이미지는 실행 중인 Python 서버에서 처리하고 `.runtime/`에 결과와 함께 보관합니다. 외부 영상 분석 서비스로 전송하지 않습니다. 로컬 사용을 기본으로 하며 인증 기능은 없습니다.

## 분석 방식과 범위

- 패드 경계는 기준 사진의 둘레를 순서대로 클릭해 등록합니다. 큰 패드와 작은 패드를 모두 지정하고 각각 LED번호를 연결하세요.
- 반복 검사에서는 업로드 전에 검사 설정을 선택하세요. 이름만으로 설정을 자동 선택하지 않습니다. 같은 ZIP에는 같은 제품·방향·촬영 구도의 사진을 넣으세요.
- 정렬은 회전 약 ±20°, 배율 0.85~1.15배, 이동 약 ±15% 범위입니다. 전체 및 패드 주변의 일치도가 부족하거나 패드가 잘린 사진은 결과 없이 오류로 표시합니다. 촬영각에 따른 원근 변형은 지원하지 않습니다. 정렬 성공은 정확도 보증이 아니므로 표시된 경계를 확인하세요.
- 같은 LED번호의 패드별 비율 중 최댓값을 화면과 CSV에 제공합니다. 현재 고객 엑셀 양식 출력은 아직 연결하지 않았습니다.
- 설정은 `.runtime/templates/`에 기준 사진과 함께 저장됩니다. 새로 등록하면 별도 설정을 생성합니다.
- 등록된 패드 안에서 여러 크기의 폐곡선 주변 대비를 이용해 보이드를 검출합니다. 절대 밝기만으로 나누지 않아 동박으로 어두워진 보이드 내부도 경계를 바탕으로 포함할 수 있습니다.
- 비율은 `패드 내부 보이드 합집합 픽셀 수 ÷ 패드 픽셀 수 × 100`입니다. 겹친 보이드는 중복 계산하지 않습니다.
- 영상 판독 기반 추정값입니다. 가려진 경계가 완전히 사라진 경우 복원이 보장되지 않으며, 실제 영상의 정답 마스크를 이용한 정확도 검증은 아직 없습니다. 합격·불합격, 체적 비율, mm²는 제공하지 않습니다.
- JPG/PNG/BMP/TIFF/WebP 및 ZIP을 지원합니다. 파일당 32 MB, 이미지당 2천만 픽셀, ZIP은 최대 100장·압축 해제 후 100 MB입니다. TIFF는 첫 프레임을 사용하며 8비트 RGB로 변환합니다.

현재 작업 환경의 판독 자료 60장은 새 자동 분석 결과와 구분해 표시됩니다. 판독 자료를 수정하거나 재분석하면 별도 결과를 만듭니다. 소스 배포본에는 고객 원본 사진이 포함되지 않습니다. 다른 환경에서는 이미지 업로드로 시작합니다. 고객 자료 다운로드 링크는 해당 보고서가 있는 작업 환경에서만 작동합니다.

## 검증

```sh
python -m unittest discover -s tests -v
```

합성 동박 단차를 가로지르는 보이드 검출, 보이드 없는 동박 경계의 오검출 방지, 빈 영상 거부, 중복 면적 계산 등을 검증합니다. 실제 영상 업로드와 화면 표시는 별도로 브라우저에서 확인합니다. Windows 실행은 이 Linux 환경에서 직접 검증하지 않았습니다.

이전 수동 데스크톱 버전은 `main.py`와 `start_windows.bat`에 남아 있습니다. 현재 기본 실행은 웹 앱입니다.

## 패드 등록 순서

1. 검사 설정을 `새 제품 — 패드 등록 필요`로 두고 기준 사진을 올립니다.
2. `현재 사진으로 패드 등록`을 누르고 설정 이름(품명·방향)을 입력합니다.
3. LED번호를 입력하고 사진에서 패드 둘레를 클릭한 다음 `패드 확정`을 누릅니다. 필요한 모든 패드에 반복합니다.
4. `설정 저장 후 보이드 분석`을 누릅니다.
5. 다음 검사부터 저장된 설정을 선택하고 사진 또는 ZIP을 올립니다.

이전 Windows 배포본 업데이트는 서버를 종료한 뒤 새 소스 파일을 기존 폴더에 덮어쓰고 다시 실행하세요. `.runtime`과 가상환경은 배포 ZIP에 포함하지 않으며 기존 자료를 유지합니다. 새 Python 패키지는 추가하지 않았습니다.

## Docker 개발 환경 (코드 수정 자동 반영)

개발은 코드를 편집하는 머신에서 컨테이너를 백그라운드 실행합니다.

```sh
docker compose up -d --build
```

해당 머신의 `http://127.0.0.1:8001`에서 확인합니다. 터미널을 닫아도 컨테이너는 실행됩니다. Python 변경은 Uvicorn이 재시작하고 HTML/CSS/JS 변경은 브라우저가 자동 반영합니다. 패드 등록·보이드 편집 중에는 화면 갱신을 보류합니다. 서버 재시작 중인 분석은 재분석이 필요할 수 있습니다. 패키지 변경은 이미지 재빌드가 필요합니다.

코드는 bind mount로 연결하고 이미지·결과·검사 설정은 호스트의 `.runtime`에 보관합니다. 개발 이미지에는 고객 파일과 가상환경을 넣지 않습니다.

관리형 클라우드에서는 인증서를 빌드에 제공하고 기존 판독 자료를 읽기 전용 마운트합니다.

```sh
docker compose -f compose.yaml -f compose.cloud.yaml up -d --build
```

클라우드의 localhost는 사용자 PC의 localhost와 다릅니다. PC에서 클라우드 앱을 보려면 플랫폼의 포트 전달 또는 미리보기 연결이 별도로 있어야 합니다. Docker 자체가 이 연결을 만들지는 않습니다. 현재 구성은 외부에 공개하지 않는 루프백 포트입니다.

### 기존 4패드 자동 등록 보조

`현재 사진으로 패드 등록` → `기존 방식으로 4패드 자동 찾기`를 누르면 중앙 2×2 배치의 패드 경계를 제안합니다. 실제 경계를 확인하고 패드별 LED 번호를 입력한 뒤 저장하세요. LED 소속은 자동 추정하지 않습니다. 다른 배치나 작은 패드에는 수동 등록을 사용하세요. 기존 등록 내용은 자동 찾기로 덮어쓰지 않습니다.
